Why agentic?

A single model must jointly solve detection, recognition, ordering and styling — with no geometric grounding and no way to check its own render. What if we decomposed instead?
The vocabulary, precisely

Agents reason. Tools execute.

𝒯A tooldeterministic

Fixed function, fixed input → fixed output. No judgment.

A layout detector always returns boxes the same way. It cannot notice that it merged two columns, or that the "table" it found is really a form.

detectors · OCR · table structure recognition
reading order · font fitting · background restoration
𝒜An agentreasons

Decides which tool, when — and whether the result is good enough.

Then retries, overrides an upstream label, reroutes to a different specialist, or injects a correction. It is allowed to disagree with what it was given.

labeling · grouping · routing
specialist generation · reading order · reflection
given I  produce  H  such that  R(H) ≈ I  across  TE, LS, PS, VF
The objective is stated on R(H) — the rendering of the HTML, not the markup itself. That one choice is what makes a Refine stage necessary.
Four questions, four stages

The pipeline, stage by stage

1Segment "How to divide the document into meaningful components?"
  • Ttype, Tdet — digital/scanned classifier; DocLayout-YOLO + IndicDLP-YOLO + Hi-SAM, fused by IoU.
  • Alab — Set-of-Mark labelling; catches mis-segmented and mixed-content regions.
  • Agrp — builds the layout graph; resolves caption–figure binding, list nesting, footnotes.
  • → hierarchical layout tree Tlayout
2Localize "How to convert each component into equivalent HTML?"
  • Aroute — picks the specialist from the crop, overriding the upstream label when the visual contradicts it.
  • 𝒜spec — six specialists: text, table, image, form, list, equation.
  • Taux — OCR, table structure, TexTAR: invoked only when necessary.
  • → sub-HTML Hv per node · conditionally independent, so parallelisable
3Assemble "How to assemble components into a coherent structure?"
  • Tpos — bottom-up merge over Tlayout, preserving containment and alignment.
  • Aro — semantic reading order (≺); spatial sorting fails on multi-column pages and floats.
  • → initial HTML document H · reading-order accuracy 0.98
4Refine "How to refine structure for visual and structural fidelity?"
  • Tfont, Tbg — non-overflow font scales by bounded search; background restored by CSS layering.
  • Aref — renders R(H), compares it to I, injects targeted CSS; up to 5 iterations.
  • → high-fidelity final HTML · the only stage that sees the render

Established axes

TE = (CRR + WRR) / 2
Character and word recognition rate.
LS = NTED · TEDS (tables) · CDM (formulas)
Normalised tree edit distance over the DOM.

Introduced in this paper

PS = (GPS + LPS) / 2
Global (layout blocks) and Local (lines) Position Score. One-to-one matching by max IoU, then area-normalised precision/recall → F1, penalising both missed elements and hallucinated boxes.
VF = VFS
Visual Fidelity Score — VLM-as-a-judge comparing R(H) against human-annotated ground truth.
Overall = ( TE + LS + PS + VF ) / 4   · CRR, WRR clipped at −1 per sample
Human validation: Pearson correlation with seven expert annotators > 0.8 across 100 documents.
Measured on VFDR-Bench — all 16 methods

Everyone passes text. The field collapses on position. — paper Table 2, live & complete

▸ Text extraction — everyone passes 0.65–0.68 WRR for the strong baselines. This axis is largely solved, which is why the field feels finished.
▸ Physical structure — total collapse Best baseline LPS 0.22, best GPS 0.43, most under 0.30. Nothing lands where it belongs.
▸ REPLICA — no weak column 0.73 / 0.86 position and 0.93 VFS. Winning one axis is easy; winning all four at once is the contribution.

Being honest about the edges

Where REPLICA still falls short

Single-page only

No multi-page consistency yet — structures spanning a page break (continued tables, figures) can fragment.

Font identification

Bold, italic, underline and colour are recovered reliably; exact font families are not. Existing methods cover mostly English/Chinese — large-scale multilingual font recognition remains open.

Rendering cost

The refine loop renders in a browser repeatedly — real latency versus a single forward pass.
