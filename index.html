REPLICA · The vocabulary, precisely

Agents reason. Tools execute.

A tool

deterministic

Fixed function. Same input, same output. No judgment.

A layout detector always returns boxes the same way. It cannot notice that it merged two columns, or that the “table” it found is really a form.

detectors · OCR · table structure
reading order · font fitting · background restoration

An agent

reasons

Decides which tool, when — and whether the result is good enough.

Then retries, overrides an upstream label, reroutes to a different specialist, or injects a correction. It is allowed to disagree with what it was given.

labelling · grouping · routing
specialist generation · reading order · reflection
The goal is that the rendered page matches the source — not that the markup looks plausible. Judging the render is what forces a Refine stage to exist at all.

REPLICA · Four questions, four stages

The pipeline, stage by stage

1Segment“How do we divide the page into meaningful pieces?”
  • A classifier decides digital or scanned; a detector ensemble proposes candidate regions.
  • A labelling agent marks each region and catches mis-segmented or mixed content.
  • A grouping agent resolves caption–figure binding, list nesting and footnotes.
  • → a hierarchical layout tree
2Localize“How do we turn each piece into HTML?”
  • A router agent picks the specialist from the crop itself — overriding the upstream label when the visual contradicts it.
  • Six specialists: text, table, image, form, list, equation.
  • OCR and table-structure tools are called only when needed.
  • → sub-HTML per region · independent, so this stage parallelises
3Assemble“How do the pieces fit together?”
  • A position-aware merge walks the tree bottom-up, preserving containment and alignment.
  • A reading-order agent linearises semantically — sorting top-to-bottom fails on multi-column pages.
  • → the first complete page · reading-order accuracy 0.98
4Refine“Does it actually look right?”
  • Font and background tools fit non-overflowing type and restore the page's backdrop.
  • A reflection agent renders the page, compares it to the source image, and injects targeted CSS — up to five rounds.
  • → the final page · the only stage that sees the render

REPLICA · Reading the scoreboard

Which metric measures what

Four axes, one metric family each. Two of the four had no metric at all before this work.

AxisThe question it asksMetricHow it is computed — in one line
Text ExtractionAre the words right? WRR · CRR standard Word- and character-level recognition rate against the reference text.
Logical StructureIs the hierarchy right? NTED · LSS standard Tree-edit distance between the produced DOM and the reference tree — reading order, nesting, tables, lists.
Physical StructureIs the position right? GPS · LPS NEW Area overlap between where each element sits in the source and where it lands in the render — GPS over layout blocks, LPS over individual lines.
Visual FidelityDoes it look right? VFS NEW A VLM judges the two rendered pages side by side on typography, colour, spacing and layout.
OverallHow good, all in? OSThe mean of the four axes — so a system cannot buy a good score by winning one axis.
Position and appearance are scored by where things land and what the page looks like — never by inspecting the markup, which is exactly how earlier benchmarks missed them.

Act I · The problemWhy grounding
The status quo

Today, grounding = emit a bounding box

Four numbers, produced the same way as any other word. Three things go wrong.

Rectangles are not enough

Document evidence is curved text, a wrapped paragraph, a slice of a chart. A rectangle cannot take that shape.

The numbers can be hallucinated

Coordinates are just more tokens to predict — nothing ties them to what is actually on the page.

One box is incomplete

Evidence is often several pieces in different places; a single rectangle either misses most of it or swallows the whole region.

Training in two stages: SFT → DPO

Stage 1 is plain supervised fine-tuning, end-to-end (VLM + GIM + mask decoder):
cross-entropy on the text · Dice + BCE on every predicted evidence mask.

Why a stage 2? SFT only imitates the single annotated chain — fixed-style supervision. It never compares the model's own better and worse chains — DPO adds that.

DoCoG · Training stage 2

DPO on text only — and the drift trap

What DPO does here

From each preference pair, DPO pushes the VLM to make the chosen ✓ chain more likely than the rejected ✗ one, against a frozen reference. Only the VLM's weights change — mask preferences are ill-posed, so GIM + segmenter stay frozen.

70.5 → 40.3
mask IoU without the fix
81.9 → 41.7
GQfa without the fix

The fix — anchor loss

𝓛anchor = (1/K) Σk ‖Gkθ − Gkref‖²

A moving VLM drags the [GND] states with it — this keeps them where the frozen GIM + segmenter expect them.

Paper 2 · DoCoGDPO + anchor loss
DoCoG · Training stage 2 · the fix

The anchor loss, unpacked

𝓛opt = 𝓛DPO + λanchor·𝓛anchor

𝓛anchor = (1/K) Σk ‖Gkθ − Gkref‖²  ·  λanchor = 1

Read the symbols

Gk = the k-th GIM-refined prompt embedding — what the mask decoder consumes · ref = frozen SFT copy · θ = the model DPO tunes · mean over the K [GND] tokens.

Why it works

Drift becomes differentiable and punished: DPO improves the reasoning only in directions that keep the grounding interface where the frozen modules expect it.

70.5 kept
mask IoU with the anchor — 40.3 without it

DoCoG · Preference data

DoCoG-PQA: 20K pairs — one gate, three scores

FR · format — the gate

Do steps, answer, and [GND] references all parse? Fail ⇒ rejected before scoring.

AQ · answer

Matches ground truth — after normalization + numeric tolerance. Rule-based, no LLM judge.

CQ · chain

ROSCOE gate (below threshold ⇒ 0), then bipartite step matching (E5 similarity) → step-level F1.

GQ · grounding

A mask counts iff IoU ≥ 0.5 + same element type + right step. All steps + answer = GQall · answer only = GQfa · GQ = mean.

✓ chosen

highest total reward — right answer and faithful grounding

✗ rejected

lowest total — a right answer can still lose on weak grounding

Same yardstick at test time: DoCoG-Bench reports exactly these metrics (deterministic, + one G-Eval) — the numbers on the next slides.
